## Behaviour
- `POST /api/sessions` → new run id `s_<8hex>`, create RunContext + EventLog in `runs/<id>/`, register in `app.RUNS` (no pipeline task), `room.ensure_room(...)`, mark the room as a **session** (`room.is_session = True`). Return `{"run_id"}`.
- `WS /ws/runs/{id}/room-audio?role=founder|judge`: read `role` from `websocket.query_params` and pass it into `room.stream_audio(run_id, websocket, role)`. `room_caption` gets `role`. Final utterances call `handle_utterance(run_id, text, role=role)`.
- In `handle_utterance` when the room is a session:
  - emit `room_utterance` with `speaker=role`. **Cross-mic dedupe:** skip if difflib ratio ≥ 0.8 vs any utterance from either role in the last 8 s.
  - role **founder** → append to `session.transcript`; emit `pitch_update`; (re)start a debounce timer: 6 s after the last founder utterance, if transcript ≥ 12 words and it grew since the last research → `session.run_research(run_id)` (max 3 research runs per session). No gate for founder speech.
  - role **judge** → existing gate; if triggered → existing `founder_brief` (no twin challenge, **no server fallback, no TTS** in sessions). Pass the judge's utterance text as the challenge. Add `matched_question_id`: the id of the prepared question with the highest difflib ratio ≥ 0.45 to the judge text, else null; include that prepared answer in the brief prompt as a hint.
  - `build_evidence` must also include the latest `pitch_research` (pitch claims, competitors, web facts, analyst probability/reason, buyer rubrics + weakest) so founder briefs and the number checker use it.
- `POST /session/pitch-done` → run research now. `POST /session/ask {text, role}` → `handle_utterance(text, role, forced=True for judge)`. `POST /session/full-run` → set `ctx.pitch={"raw_text": transcript}` and start `orchestrator.run_pipeline(ctx, log)` as a background task (store it in RUNS).

## `session.run_research(run_id)` (async; everything in parallel where possible; emit `research_status` running/done/failed per step)
1. **pitch** — `generate_json(MODEL_IDS["pitch_extract"], transcript, schema, thinking="low")` → `{title, one_liner, target_user, price_usd|null, location|null, claims[] (≤5)}`.
2. In parallel (`asyncio.gather`, each with its own timeout, failures don't block others):
   - **competitors** (Shopify, timeout 15 s) — top 3 `{title, price_usd, url}` for `one_liner`.
   - **web** (timeout 30 s) — `client().interactions.create(model=MODEL_IDS["persona_driver"], input=<prompt>, tools=[{"type":"google_search"}], generation_config={"thinking_level":"low"})` (verified working) asking for 3 short facts a skeptical investor should know about this product's market: existing competitors/brands (esp. in the stated location), recent market facts, regulatory or safety issues — each with a source URL. Parse into `[{fact, url}]` with `generate_json` (Hydrogen, low) from the text.
   - **analyst** (timeout 30 s) — `analyst._analyse_sync(pitch)` → `{probability, reason, framing=campaign_text}`.
   - **buyers** (timeout 25 s) — 200 personas from `backend/panel_200.json`, same 5 RUBRICS as swarm.py (all `noul`), one Decisions call (chunk 250 if needed), text-only input = pitch + competitors; per-persona weighted geometric mean → `intent_mean`; rubric means; `weakest` = lowest rubric id.
   Emit `pitch_research` after step 1 + fast parts, and again when all are done (complete). Include `latency_ms`.
3. **questions** — `generate_json(MODEL_IDS["strategist"], ..., thinking="low")` (Neon) → exactly 3 `{id: q1..q3, question (≤25 words, as a sharp judge would ask it out loud), why (≤15 words), evidence (≤20 words, a concrete fact or number from the research), source}`. Prefer: one competitor/web question, one buyer-weakness question, one economics/feasibility question. Emit `judge_questions`.
4. **prep** — `generate_json(MODEL_IDS["room_founder"], ..., thinking="low")` (Hydrogen) → for each question `{question_id, question, line (≤22 words, first person, honest — concede when evidence is against the founder and give the plan), points (2 short bullets), evidence}`. Emit `founder_prep`.
Store the latest research/questions/prep on the session object. Target: first questions on screen ≤ 30 s after the founder stops talking.
